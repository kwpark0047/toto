# w-toto — QR·NFC 메뉴판 주문·매장 관리 플랫폼(모듈형 멀티테넌트)

테이블 QR/NFC로 **메뉴 보기 → 주문 → 주방(4단계) → 결제 확인 → 매출·회원·리뷰**까지,
그리고 **재고·예약·웨이팅·직원(역할·권한·스케줄·예상 급여)·매장 그룹·온라인 주문·결제수단·이벤트·로컬 커뮤니티·인쇄물**까지 담은 플랫폼입니다.
배포 하나에 **여러 사업자가 가입**해 각자 매장을 운영하고, 계정·매장 데이터는 완전히 분리됩니다.

> 파이썬 3.10+ 표준 라이브러리 + SQLite/Turso. 외부 패키지 설치 없이 실행됩니다.
> QR 그림(PNG)만 Pillow가 있으면 글꼴까지, 스캔 검증은 OpenCV가 있으면 자동 확인합니다(없으면 생략).

## 1. 실행

```bash
cd /workspace/menu-platform
python3 server.py                 # http://localhost:8000
python3 server.py --port 8100     # 포트 바꾸기
python3 server.py --reset         # 데이터를 지우고 처음부터
```

- **처음 실행하면 계정이 없습니다.** `http://localhost:8000/signup` 에서
  **매장 이름(기본 "맛집") + 아이디·비밀번호** 두 칸만 넣으면 바로 시작합니다.
- 나머지(사업자 정보·영업시간·직원·테이블·재고)는 로그인 후 각 화면에서 하나씩 추가합니다.
- 휴대폰에서 보려면 PC와 같은 와이파이에서 `http://<PC IP>:8000` 으로 접속합니다.
  **음성 주문·브라우저 알림은 https 또는 localhost에서만 동작**하므로, 랜 주소(http)로 열면
  마이크·알림이 막힙니다(화면에 안내가 나옵니다).

### 로그인 · 소셜 로그인(구글·카카오)

`/login` · `/signup` 한 화면에서 아이디 로그인과 회원가입을 탭으로 오갑니다. 비밀번호 보기 토글,
입력 안내, 소셜 버튼(카카오 `#FEE500` · Google 공식 G 로고)이 함께 있습니다.

소셜 로그인은 **앱 키(환경변수)를 넣으면 바로 동작**하고, 키가 없으면 가짜 로그인을 만들지 않고
`configured: false` 와 "앱 키가 연결되지 않았습니다" 안내를 보여 줍니다.

| 환경변수 | 필수 | 설명 |
|---|---|---|
| `GOOGLE_CLIENT_ID` | 구글 사용 시 | Google Cloud OAuth 2.0 클라이언트 ID |
| `GOOGLE_CLIENT_SECRET` | 구글 사용 시 | 같은 클라이언트의 보안 비밀 |
| `KAKAO_CLIENT_ID` | 카카오 사용 시 | 카카오 디벨로퍼스 **REST API 키**(앱 키) |
| `KAKAO_CLIENT_SECRET` | 선택 | 카카오 '보안 → Client Secret'을 켠 경우에만 |
| `OAUTH_BASE_URL` | 권장 | 공개 주소(예: `https://w-toto.vercel.app`). 없으면 요청 Host로 추론 |

등록할 리다이렉트 URI(제공자 콘솔에 그대로 넣기):

```
https://<공개주소>/api/auth/oauth/google/callback
https://<공개주소>/api/auth/oauth/kakao/callback
```

- `GET /api/auth/oauth/providers` — 제공자별 `configured`·리다이렉트 URI 확인(키 노출 없음).
- `GET /api/auth/oauth/google|kakao` — 302로 제공자 인가 화면 이동(state 쿠키 10분, HttpOnly).
- `GET /api/auth/oauth/<provider>/callback` — state 검증 → 토큰·프로필 교환 → `oauth_accounts` 연결 → 세션 쿠키.
- 아직 사장님 계정이 없는 첫 방문이면 매장과 사장님 계정을 함께 만들고, 이미 매장이 있으면
  연결되지 않은 소셜 계정으로 관리자 계정을 새로 만들지 않고 아이디 로그인을 안내합니다.

### 역할과 권한

역할은 **사장님 · 점장 · 매니저 · 카운터 · 홀 · 주방 · 알바(시간제)** 7가지입니다.
역할마다 기본 권한이 있고, **직원마다 체크박스로 예외**를 줄 수 있습니다(사장님은 항상 전부).

| 권한 | 사장님 | 점장 | 매니저 | 카운터 | 홀 | 주방 | 알바 |
|---|:--:|:--:|:--:|:--:|:--:|:--:|:--:|
| 메뉴 수정 | ✅ | ✅ | ✅ | – | – | – | – |
| 가격 변경 | ✅ | ✅ | ✅ | – | – | – | – |
| 품절 처리 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | – |
| 주문 상태 변경(조리) | ✅ | ✅ | ✅ | – | ✅ | ✅ | ✅ |
| 주문·결제 확인 | ✅ | ✅ | ✅ | ✅ | ✅ | – | ✅ |
| 주문 취소·환불 | ✅ | ✅ | ✅ | ✅ | – | – | – |
| 고객 정보 열람 | ✅ | ✅ | ✅ | ✅ | ✅ | – | – |
| 매출 조회 | ✅ | ✅ | ✅ | ✅ | – | – | – |
| 직원 관리 | ✅ | ✅ | ✅ | – | – | – | – |
| 설정 변경 | ✅ | – | – | – | – | – | – |
| 주방 화면 | ✅ | ✅ | ✅ | – | – | ✅ | – |

- 권한이 없는 화면은 **403 안내 화면**(필요한 권한 이름 표시)으로 막고, 상단 메뉴에서도 숨깁니다.
- API도 같은 권한으로 막습니다(화면만 숨기는 방식이 아님). 매출 권한이 없으면 사장님 화면의 금액도 숨깁니다.
- **알바(시간제)는 시급제**로 표시되고 근무시간·예상 급여 계산에 반영됩니다.
- 관리자는 직원 비밀번호를 **초기화**(임시 비밀번호 1회 발급)할 수 있고, 직원은 `/account`에서 직접 바꿉니다.
  비밀번호는 pbkdf2-sha256 해시로만 저장합니다.

## 2. 화면별 기능

### 고객 (`/t/<코드>`)
- 추천 메뉴 → "또 시킬까요?" → 카테고리 탭 → 메뉴 카드 → 장바구니 → 주문.
- 원산지·알레르기·매운맛 표시(없으면 "정보 없음"), **말로 주문**(확인 후 담김).
- 포인트 사용·현금영수증 요청·주문 취소(접수 전)·직원 호출.
- **진행 4단계**: 접수 → 조리 중 → 조리 완료(서빙 준비) → 서빙 완료. 단계별 시각·경과·예상 시간, 자동 갱신.
- **리뷰**: 조리 완료·서빙 후 별점(1~5)과 한 줄 평가(선택). 주문 1건당 1개, 이름·연락처는 받지 않습니다.
- 화면 설정(큰 글씨·고대비·움직임 최소)·읽어 주기(TTS)·언어 4종.

### 주방 (`/kitchen`)
- 큰 글씨 KDS, 5분 주의·10분 지연, 새 주문 소리/음성, 화면 유지.
- **4단계**: 접수 → 조리 시작 → 조리 완료 → **서빙 완료**. 조리 완료는 별도 **서빙 대기** 줄에
  경과 시간과 함께 남고, 서빙 완료를 누르면 목록에서 사라집니다.
- 알레르기 강조·전용 알림음, 메뉴별 묶음 탭, 직원 호출 처리.

### 사장님 콘솔 (`/admin`)
- 오늘 주문·결제 확인 매출·미수금·주방 대기, 현금 받음, 상태 전이(4단계), 테이블 현황(좌석·머문 시간·금액).
- 웨이팅 요약, 호출 목록, 오늘 잘 팔린 메뉴, 영수증 미리보기, 포인트·현금영수증 표시.

### 매출·정산 (`/revenue`)
- 기간: **오늘 / 이번 주 / 이번 달 / 직접 선택**.
- **일별 표·시간대별 표**, 결제수단별(현금만 실제, 카드는 "PG 미연동"으로 0원 표시).
- **인기 메뉴·카테고리 비중**, 취소 건수·금액과 **할인(포인트 사용)**을 실제 결제액과 분리.
- **미수금(결제 전)** 과 **결제 확인 금액** 분리. **CSV 내보내기**(엑셀에서 한글 안 깨지게 BOM).

### 재고·재료 (`/inventory`)
- 재료 등록(이름·단위·현재고·안전재고), 입고·실사 조정 기록.
- **메뉴별 소모량(레시피)** 을 정해 두면 **현금 결제 확인 때 자동 차감**, 결제 취소·주문 취소 때 복원.
  같은 주문을 다시 확인해도 두 번 차감하지 않습니다.
- **안전재고 미만 경고**, 재고가 모자란 재료를 쓰는 메뉴의 **품절 제안 버튼**.
- 자동 발주·거래처 전송은 하지 않습니다.

### 예약 (`/reservations` · 손님 `/reserve`)
- 사장님: 날짜·시간·인원·연락처·메모·테이블(선택)으로 등록, **월 캘린더**, 일자별 목록,
  상태(신청 → 확정 → 도착 / 노쇼 / 취소), 오늘 예약 요약.
- 손님: QR·링크로 **예약 신청**만. 확정은 사장님이 직접 누릅니다. 신청 후 확인 링크(`?t=토큰`)로 상태를 봅니다.

### 리뷰 (`/reviews`)
- 손님 별점·한 줄 평가 → 사장님 목록, **답글 메모**, **숨김**(숨긴 리뷰는 평균에서 제외).
- 평균 별점·별점 분포·최근 7일 추이. 외부 플랫폼 연동은 없습니다.

### 매장(다점포) (`/stores`)
- **사업자 계정별 매장 분리**: 배포 하나에 여러 사업자가 가입하고, 각 계정은 자기 매장만 봅니다(다른 계정 매장은 404).
- 매장 추가(상호·테이블 수·메뉴 새로/복사), 상단 **매장 전환**(사장님만), 사용 안 함, 공개 목록 노출 ON/OFF.
- **메뉴·주문·직원·회원·매출·재고·예약·리뷰·설정이 매장별로 분리** 저장·조회. 기존 데이터는 1번 매장 그대로.
- 선택한 매장 기준으로 `/tables`·`/qr`·`/menu`·`/staff`·`/revenue`가 모두 그 매장 데이터를 씁니다.
- **전 매장 통합 대시보드**: 오늘·이번 달·누적 매출과 주문 합계, 매장별 매출 비중 막대·비교 표.
- **메뉴 복사**: 원본→대상 매장, 전체/선택 메뉴, 같은 이름은 건너뛰기/덮어쓰기. 카테고리·가격·설명·옵션·사진·추천·원산지·알레르기까지 복사.
- **직원 이동(발령)**: 역할·권한은 그대로 두고 소속 매장만 이동, 로그인 세션도 새 매장으로. `staff_transfers`에 이력.
- **매장 그룹**: 브랜드/지역/직영/가맹으로 묶어 그룹 통합 매출·메뉴 일괄 복사·그룹 내 직원 이동·그룹 설정(운영 모드·웨이팅) 일괄 적용.
  `GET/POST /api/groups`, `GET /api/groups/<id>/summary`, `POST /api/groups/<id>/copy-menu`, `POST /api/groups/<id>/apply-settings`.
- 매장 공통 QR은 `/?store=<id>`, 웨이팅 접수·보드는 `/wait?store=<id>` 로 그 매장 화면이 열립니다(1번 매장은 주소가 그대로).

### 온라인 주문 · 운영 모드 · 구역 (`/online` · `/order` · `/tables`)
- 매장 설정에서 **오프라인(테이블 QR·NFC) / 온라인(포장·배달·사전주문) / 통합** 모드를 고릅니다.\n  온라인 전용이면 테이블 주문을 거부하고, 꺼 둔 포장·배달 주문은 API에서도 거부합니다.
- `/online?store=<id>`: 손님 포장·배달 주문 화면(받는 방법·연락처·배달 주소·결제 방법·입금자명).
- 테이블 **구역**(홀·창가·테라스) CRUD, 구역별 테이블 한 번에 만들기(예: 창가1~창가6), 구역 이동·삭제 시 테이블 자동 재배치.

### 결제 (`/admin` · 설정 → 결제 수단)
- **현금**(항상) · **계좌이체**(은행·계좌·예금주 → 손님 입금자명 → 사장님 입금 확인 → 결제 완료) · **카드/간편결제**(매장 설정 ON/OFF, 수수료율·안내 문구).
- **PG 연동 대비 어댑터**: 키가 없으면 **모의 승인(simulated)** 으로만 기록하고 API·화면에 “실제 결제 아님”으로 표시합니다. 수수료 합계·환불 내역 제공.
  `GET /api/payments/methods`, `POST /api/orders/<id>/transfer`, `/pay`, `/payment-confirm`, `/refund`, `GET /api/payments/summary`.

### 고객 이벤트·쿠폰 (`/customers` · 설정 → 고객 이벤트)
- 첫 방문·재방문(며칠 안)·생일 포인트/쿠폰 자동 지급, **시간 할인**(구간·할인율) 자동 적용, 쿠폰 발급·사용·취소 시 복원.
- 손님은 주문서에서 연락처로 쿠폰을 확인해 쓸 수 있습니다(`GET /api/member/coupons?phone=`).

### 로컬 커뮤니티 (`/community`)
- 동네 소식·단골 공지·동네 이벤트·공동 프로모션 글. 매장/그룹 범위, 손님 노출 ON/OFF.
- 커뮤니티를 켜고 “손님에게 보이기”를 켜야 손님 메뉴 화면 하단에 나옵니다. 다른 사업자 매장에는 보이지 않습니다.

### 회원 (`/customers`)
- 등급(신규/단골/VIP) 자동·수동, 포인트 적립·사용·이력, 생일, 방문 이력, 즐겨 찾는 메뉴, 쿠폰 발급·상태, 합치기, CSV.

### 웨이팅
- 전화번호 필수 접수·번호표(앞 팀·예상 시간)·개인 링크·번호 찾기·호출/입장/취소/노쇼·선주문,
  **설정에서 ON/OFF·안내 문구·한 팀 최대 인원** 적용, 입장·취소 후 24시간 지나면 개인정보 자동 삭제, 브라우저 알림(탭 열림 시).

### 직원 (`/staff`)
- 역할 7종, **권한 예외 체크박스**, 시급/월급, 비활성, 근태·CSV.
- **근무 스케줄표**: 주/월 표, 오늘 근무자 요약, 실제 출퇴근과 대조해 **지각(10분 초과)·미출근** 표시.
- **예상 급여(참고용)**: 시급제는 실제 근무시간×시급, 월급제는 월급. 직원별·월별 목록과 CSV.
  **세금·4대보험·급여명세서는 하지 않습니다("참고용, 세무는 별도").**
- 출퇴근 누락 보정(사장님) 기능이 있습니다.

### 테이블 / 설정 / QR·인쇄
- 테이블 추가·이름·좌석·순서·비활성·**구역**, QR·NFC 주소 자동, 구역별 일괄 생성.
- 설정은 카드형 접이식(기본·사업자·영업시간·포인트/등급·알림·**운영 모드·결제 수단·고객 이벤트·로컬 커뮤니티·웨이팅**·직원·테이블·백업). 비워 두어도 주문은 그대로.
- 디자인 QR(점·색·배지·문구, 실제 디코딩 검증·단계적 후퇴), **NFC 태그 URL(?via=nfc)·NDEF 쓰기 안내**, **QR 대비 NFC 유입 통계**(테이블별),
  테이블 메뉴판(A5/A6)·웨이팅 안내물(B4/A3), A4/B4 다중 배치, 화면 인쇄 + PDF.

- 문의: `POST /api/public/inquiries` → 접수번호(WT-YYYYMMDD-0001) 발급. 사장님 콘솔 `/settings`에서 `GET /api/inquiries`로 확인.

## 8. 보안·개인정보(시제품 기준)

- 비밀번호는 pbkdf2-sha256 + 계정별 salt 해시. 세션은 서버 저장 + HttpOnly 쿠키, 12시간 만료.
- 같은 아이디 5회 실패 시 5분 잠금. 비밀번호 변경·초기화 시 다른 기기 세션 종료.
- **매장 분리**: 모든 업무 데이터에 `store_id`가 붙고, 요청마다 그 요청의 매장 안에서만 읽고 씁니다.
  다른 매장 데이터는 목록·합계에 섞이지 않습니다.
- 고객 이름·연락처는 주문 동의 시에만, 웨이팅·예약 연락처는 목적 안내 + 웨이팅은 24시간 후 자동 삭제.
- 로그인하지 않은 손님에게 주문 조회는 상태·메뉴만 주고 **이름·연락처는 돌려주지 않습니다**.
- 매출 권한이 없으면 사장님 화면의 금액을 숨깁니다.
- 외부 전송 없음(문자·카카오·PG·푸시 모두 미연결). 데이터는 `data/mangjip.db` 한 파일.
- 실제 운영 전에는 **HTTPS + 본인인증/사업자 진위확인 + 백업 외부 보관·접근제어**가 필요합니다.
